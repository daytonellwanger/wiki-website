# Constraints

<!-- purpose
Things about the codebase that can't be logically deduced from reading it — historical reasons, external agreements, or migration artifacts that explain why code looks the way it does.

For example: a seemingly redundant field that exists because of a migration that happened three years ago, or a library choice locked in by a vendor contract.

Without this, engineers and LLMs will "fix" things that aren't broken, or spend time trying to understand code that simply cannot be understood from first principles. This is distinct from [limitations](../limitations/overview.md), which documents genuine areas for improvement.

This is an overview — keep each constraint brief and link to individual files in this directory for more detail.

If it was an active architectural decision rather than an external or historical constraint, consult [adrs/](../adrs/overview.md) to see if it better fits there.
-->
